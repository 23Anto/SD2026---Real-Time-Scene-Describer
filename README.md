# Real-Time Scene Describer

A wearable-style "scene describer": a small camera streams video over Wi-Fi, and a
laptop runs computer-vision models on that video to say what's in front of you.

There are two halves to this project:

1. **The camera (hardware)** – a Seeed **XIAO ESP32-S3 Sense** board with an OV3660
   camera. It runs C firmware that connects to Wi-Fi and serves a live video stream
   over HTTP.
2. **The laptop (software)** – Python scripts that pull that video stream (or a
   plain webcam) and run object detection / text reading on it, drawing boxes on
   screen and, in one case, speaking the results out loud.

You can run all the Python scripts against a **normal laptop webcam** without any
hardware, which is the easiest way to get started.

## The models (what changed and why)

The original scripts used only **EfficientDet-Lite2** (a TensorFlow Lite model,
loaded through Google's MediaPipe library). Two things were added:

### 1. YOLOv8n (`live_preview_yolo.py`)
A second, newer object-detection model (from the `ultralytics` library) so the two
can be compared side by side. YOLOv8n is generally faster and more accurate on
everyday objects. Both preview scripts use the **same color code** so results line
up:

- **Green box** – confidence ≥ 0.70 → this is what the real product would announce.
- **Yellow box** – confidence 0.30–0.70 → detected, but not confident enough.
- **Red box** – confidence < 0.30 → very weak, basically noise.

The scripts detect down to a low floor (0.15) on purpose, so you can *see* the weak
detections instead of them being silently dropped.

### 2. Shared video source (`video_source.py`)
Before, each script was hard-coded to `cv2.VideoCapture(0)` (laptop webcam) or had
an ESP IP address pasted into it. Now every script calls `open_video_source()`,
which checks the **`VIDEO_SOURCE`** environment variable:

- not set → laptop webcam (camera index 0)
- `VIDEO_SOURCE=1` → second camera
- `VIDEO_SOURCE="http://<esp-ip>/stream"` → the ESP32 camera

`video_source.py` also contains `MJPEGStream`, a small class that decodes the
ESP32's video format (a stream of JPEG images) and behaves like a normal OpenCV
camera object.

The EasyOCR script (`test_camera.py`) always needs the ESP stream; it reads the
same `VIDEO_SOURCE` variable and falls back to `DEFAULT_ESP_URL` in
`video_source.py`.

## Running the Python scripts

### One-time setup

```bash
cd SD2026---Real-Time-Scene-Describer

# Use the existing virtual environment (already has the packages):
source .venv/bin/activate

# ...or make a fresh one:
python3.9 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

> Note: `requirements.txt` pins `mediapipe==0.10.14` on purpose — newer versions
> crash on macOS inside the object detector.

### Run against a laptop webcam (no hardware needed)

```bash
python live_preview_yolo.py     # YOLOv8n live boxes    – press q to quit
python live_preview.py          # EfficientDet live boxes – press q to quit
python test_mediapipe.py        # press SPACE to describe a frame, q to quit
```

### Run against the ESP32 camera

1. Power the ESP32 and wait for it to join Wi-Fi (see the hardware section).
2. Find its IP address (see "Finding the camera's IP" below). Say it's
   `192.168.1.223`.
3. Point any script at it:

```bash
export VIDEO_SOURCE="http://192.168.1.223/stream"

python live_preview_yolo.py
python live_preview.py
python test_camera.py           # OCR + speaks detected text aloud
```

To go back to the webcam: `unset VIDEO_SOURCE`.

### Picking the model file

- `live_preview.py` / `test_mediapipe.py` look for `efficientdet_lite2.tflite` next
  to the script. Override with `MODEL_PATH=/path/to/model.tflite`.
- `live_preview_yolo.py` looks for `yolov8n.pt` (auto-downloads if missing).
  Override with `YOLO_WEIGHTS=/path/to/weights.pt`.

## The ESP32 camera (hardware)

### What you need

- Seeed **XIAO ESP32-S3 Sense** board with the OV3660 camera attached
- USB-C cable
- **ESP-IDF v5.1 or newer** installed ([official install guide](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/get-started/))

### Set the Wi-Fi network

The Wi-Fi name and password are currently written directly in
`main/camera_streamer.c` near the top:

```c
#define CONFIG_ESP_WIFI_SSID      "ATT678zcD2"
#define CONFIG_ESP_WIFI_PASSWORD  "2udi62ppa78y"
```

Change those two lines to your own network before building. The board only joins
**2.4 GHz** networks (not 5 GHz).

### Build, flash, and watch the logs

```bash
# Load the ESP-IDF environment (path depends on where you installed it):
. $HOME/esp/esp-idf/export.sh

cd SD2026---Real-Time-Scene-Describer

idf.py set-target esp32s3     # only needed the first time
idf.py build
idf.py -p /dev/tty.usbmodem* flash monitor
```

`monitor` shows the serial log. Press `Ctrl+]` to exit it.

### Finding the camera's IP

**Option A – serial log.** While `idf.py monitor` is running, look for a line like:

```
I (5123) XIAO_CAM: Got IP Address: 192.168.1.223
```

**Option B – scan the network.** From a machine on the same Wi-Fi:

```bash
# Look for a device whose page is titled "XIAO Camera"
for i in $(seq 1 254); do
  curl -s -m 1 "http://192.168.1.$i/" | grep -q "XIAO Camera" && echo "Camera at 192.168.1.$i"
done
```

**Option C – browser.** Open `http://<ip>/` and you should see the live video.
The raw stream is at `http://<ip>/stream`.

> The IP is assigned by your router and **will change** from time to time (e.g. when
> switching between a home network and a phone hotspot). Whenever detection scripts
> can't connect, re-check the IP and update `VIDEO_SOURCE`.

### How the stream works (quick version)

The firmware serves an **MJPEG** stream: an endless HTTP response made of
back-to-back JPEG images separated by a `--frame` marker. The sensor runs at
~640×480, ~10 frames per second (`vTaskDelay(100 ms)` in `stream_handler`). The
`MJPEGStream` class in `video_source.py` splits that response back into individual
frames for OpenCV.

## Typical "take it over" checklist

1. `source .venv/bin/activate`
2. `python live_preview_yolo.py` — confirm detection works on your webcam.
3. Edit the Wi-Fi lines in `main/camera_streamer.c`, then
   `idf.py build flash monitor` to get the board online.
4. Note the IP from the serial log, `export VIDEO_SOURCE="http://<ip>/stream"`.
5. `python live_preview_yolo.py` again — now you're detecting on the ESP camera.
6. `python test_camera.py` — OCR + spoken output over the same stream.

## Troubleshooting

| Problem | Fix |
|---|---|
| `Could not open video source.` | Wrong `VIDEO_SOURCE` / camera in use by another app / ESP offline. |
| Script connects then hangs on a frozen frame | ESP stream dropped. Restart the script; power-cycle the board if needed. |
| `mediapipe` crash on macOS ("DrishtiMetalHelper ... Service is unavailable") | Make sure `mediapipe==0.10.14` (not 1.x). Reinstall from `requirements.txt`. |
| ESP never prints an IP | Wrong Wi-Fi credentials, or a 5 GHz network. Use 2.4 GHz. |
| No sound from `test_camera.py` | `pyttsx3` needs a system TTS voice; check your OS audio output. |
| `idf.py: command not found` | You didn't run `. $IDF_PATH/export.sh` in this shell. |
